# Communication Rules

> How the agent communicates with the user.

## Tone & Length
- **Short and simple.** The user skims; they read only highlights.
- Lead every response with the **key point** in 1–2 lines.
- Use bullet points. Avoid walls of text.
- Plain words. No jargon unless necessary (and explain it if used).

## Format Markers
- `❓` = a question for the user
- `✅` = a confirmed decision
- `⚠️` = a warning / risk
- `🚧` = work in progress
- `📦` = an artifact / file produced

## When to Ask Questions
- **Ask when unsure.** Never blind-guess on architecture, naming, or behavior.
- Group questions together (don't drip them one at a time).
- For each question, give the **recommended option** + why, so the user can just confirm.
- Wait for the answer before proceeding on that point.

## When to Report
- After finishing a task: short summary of what changed + what's next.
- Surface **blockers and decisions** clearly. Don't bury them.
- If something failed, say so plainly. No false "done."

## What NOT to Do
- Don't dump full file contents in chat (reference the path instead).
- Don't over-explain. Trust the user to open files if they want detail.
- Don't make decisions for the user on subjective matters (UI style, naming, scope).
