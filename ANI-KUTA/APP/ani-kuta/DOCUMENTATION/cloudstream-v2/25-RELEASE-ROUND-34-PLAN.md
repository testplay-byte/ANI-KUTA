## The key decisions

- **D-415 (the share robustness):** the export flow gets (a) a hard 12s total `withTimeout`, (b) a 4s `withTimeout` around the icon fetch (a trickle server could previously stretch `readBytes()` across many 2.5s read windows = the "loading forever" report), (c) pre-flight source-file checks with a SPECIFIC message ("The plugin file is missing — reinstall the plugin and try again"), (d) the ContextWrapper unwrap to the Activity (`findActivity()`) with `FLAG_ACTIVITY_NEW_TASK` only when launching from a non-activity context (the background-launch silent-block class), (e) specific failure toasts + the CancellationException rethrow (cancellation never shows a false error), (f) stale-export cleanup (>1h) so cacheDir never grows unbounded, (g) the icon-fetch failure = share WITHOUT the embedded icon (never a failed share).
- **D-416 (the co-install line):** `debug { applicationIdSuffix = ".debug"; versionNameSuffix = "-debug" }` in :app. Every provider authority (`${applicationId}.fileprovider`, androidx-startup) + `context.packageName` follow the suffix automatically (verified: the share code builds the authority from `context.packageName`). The debug overlay (app/src/debug/res) restores the old lime icon + the "ANI-KUTA Debug" label. The committed anikuta-debug.keystore keeps every debug build cross-installable.
- **D-417 (the launcher-icon system):** 8 activity-aliases (`.icons.IconV1..V8`), MAIN/LAUNCHER removed from MainActivity (the deep-link/other filters stay; exported stays). Default (V1) = the user's icon; V2..V8 = the generated variants. Switching = `PackageManager.setComponentEnabledSetting` (enable-new before disable-old, DONT_KILL_APP; component class names are NAMESPACE-based `com.confused.anikuta.icons.IconV{n}` while the package part is `context.packageName` — the suffix-safe construction, verified against the built APK with aapt2 post-build). Resource set: adaptive bg WebPs (432px, referenced from mipmap-anydpi-v26 XMLs) + legacy WebPs (48..192, all 5 densities, all 8 variants) + the old main `mipmap-anydpi` vectors DELETED (they outranked density buckets on API<26) + picker previews (drawable-nodpi, 192px).
- **D-418 (the App Icon page):** `AppearanceScreen` reordered General → Episode List → Details page → **App Icon** (the last row, directly below the Details page row — the user's exact words). New `AppIconScreen` + `AppIconController` + `AppIconPreferences`: current-icon hero, the 8-variant grid (radio-selected, tap = alias switch + a "may take a few seconds" note), the GitHub catalog section (live fetch `GET /repos/Confused-Creature-180/ANI-KUTA/contents/icons`, filename→variant matching by the `icon-NN` prefix, extras = in-app only + honest label), the custom-image row (SAF image picker → square center-crop → in-app current icon), catalog refresh + offline cache (filesDir/app-icons/).
- **D-419 (the debug descriptions):** the three subtitles replaced with the exact minimal strings; everything else in the rows untouched.
- **D-420 (the signing):** the keystore is generated LOCALLY (keytool, JDK 21) and the SIGNED build is produced by a LOCAL Gradle build (the Android SDK is installed in the sandbox this round — dl.google.com verified reachable, 153MB cmdline-tools in 1.7s) so the keystore + passwords NEVER touch GitHub, not even as Actions secrets. CI keeps its unsigned-verification role (push → tests + assembleDebug + assembleRelease R8). NO `v*` tag is pushed this round (release-apk.yml would auto-publish a debug-signed APK — the v1.1.1 release is created BY THE USER on the new repo from the delivered zip).
- **The delivery zip** (AES-256 via pyzipper): `ani-kuta-v1.1.1-release.apk` (signed), `ani-kuta-v1.1.1-debug.apk` (co-installable), `anikuta-release.keystore`, `keystore.properties`, `SIGNING-DETAILS.txt` (the five details), `icons/` (8 × 512px PNGs for the new repo), `README-FIRST.txt`. Uploaded as a release asset (tag `assets-v1.1.1-delivery`, deliberately NOT `v*`) on testplay-byte/ANI-KUTA — deleted after the user confirms safekeeping (the user's own instruction: "Later on we will delete it from GitHub").
