# Round 123 — The Lying Event Map, the VALIDATED Gate, the Preserved Partials, and the Staleness Batch

> THE ORDER (the user's round-122 device report): the downloaded episode said "Resumed 12:44" but played from 0:00 while streaming worked — "there is a logical glitch which is hidden"; a failed episode STILL pinned the bar at the very end and the Up Next card appeared DURING the failure; Up Next fired "way too early" with a nonsense countdown and a dismissed card never returned on replay; AniSkip is "not working at all" (no pills, no ribbon); the episodes drawer did NOTHING in fullscreen landscape; offline resume STILL errored ("unable to resolve host") and healed tasks "resumed from the very start"; drag reorder "way too glitchy… ugly"; the database is not updated on refresh (library shows the old title, tags/status blank on reopen); and "there should be proper logcat monitoring" — the next report ships with logcat. ## 1. The lying event map (D-762)

**The hidden logical glitch was found — the app's MPV event constants were WRONG.** `PlayerObserver` declared `FILE_LOADED = 11` and `PLAYBACK_RESTART = 17`, but mpv's real ids are `MPV_EVENT_FILE_LOADED = 8` and `MPV_EVENT_PLAYBACK_RESTART = 21`; 11 is `MPV_EVENT_IDLE` and 17 is `MPV_EVENT_VIDEO_RECONFIG`. The consequences: mpv's startup IDLE event bumped `fileLoadedGeneration` before ANY file existed — the round-122 resume seek (which correctly keys on that generation) fired into an empty core and mpv silently dropped the seek, while the REAL FILE_LOADED (8) fell through to the default handler. The pill told the truth about the DECISION and lied about the SEEK. Worse, `eventName()` used the same scrambled map, so every log line mislabeled its event — the logcat could never reveal the bug because the logger itself was lying. Fixed: all eleven constants corrected to mpv/client.h's true values (`MPV_EVENT_NONE = 0` added), `eventName()` rewritten to the correct mapping, and `onEvent` now logs `rawId=$eventId` alongside the name so a future mismatch is visible. The resume seek additionally VERIFY-POLLS now: capture the generation at effect start (`genAtLoad` — a delegated read inside the effect would compare the live state to itself and always pass), then 10×200ms polls demand the live position move toward the target; one re-issue mid-poll, and an OK/NOT-VERIFIED verdict is logged either way. R2's failure chain needed the same map fix — the "eof" the failed episode kept saving was IDLE-and-reconfig noise all along.

## 2. The failure freeze (D-763)

The failed-episode end-pin needed one more gate the event map had masked: once `loadingState` is ERROR, the time-pos and duration handlers in `PlayerObserver` return WITHOUT updating the holder (a dead stream's demuxer EOF fires eof-reached with no error event, and keep-open pins time-pos at EOF — that combination used to look identical to a finished episode). `updateError` and `setSwitchingError` now zero the playback metrics after setting ERROR (`resetPlaybackMetrics()` — a fresh episode starts from a clean slate, not the corpse's), and the EOF history write, the Up Next offer, and the pre-switch save all demand `episodeReachedPlayback && loadingState != ERROR`. The card the user saw DURING the failure was the ungated EOF force-offer; it cannot fire anymore.

## 3. Up Next sanity + the honest countdown + the expiring dismissal (D-764)

"Way too early" had two roots. Cross-file pairing: before the new file's own time-pos arrives, the poll could pair the OLD file's end position with the NEW file's duration — fraction ≥1, card fires instantly. Implausible stamps: a manual outro recorded at 8% of the episode fired the card a fifth of the way in. The evaluation is now gated (`!isSwitching && episodeReachedPlayback && loadingState != ERROR`), demands `fraction >= 0.95` OR a PLAUSIBLE outro (`outroStart >= duration*0.5 && < duration-5`) actually reached, and logs the full evaluation each tick. The countdown holds at full until the position is past 95% — a timer that ticks down from "a lot of time left" is dead. And the dismissal expires on a REPLAY: `offeredNextKeys`/`dismissedNextKeys` clear for the episode after `resetAutoMarkSuppressed()` (a fresh playback re-arms the offer) while the orientation-change path still preserves them.

## 4. AniSkip latch v2 (D-765)

The round-122 POST client fixed the network side, but every episode that had FAILED under the old GET client still carried a stale negative latch in prefs under `pref_episode_skip_asked_<ep>` — "asked, answer: nothing" — so the fetch effect short-circuited forever. The key prefix is now **`pref_episode_skip_asked_v2_`** (the one-time latches invalidate wholesale; the D-122 key-version doctrine), and the fetch decision (`malId=… anilistId=… durSec=… latched=…`) logs one line so a silent fetch is distinguishable from an unasked one.

## 5. The drawer that composed UNDER the player (D-766)

Three-dots → nothing in fullscreen: `AnimatedContent` stacks sibling composables in composition order, and the drawer was composed BEFORE the player surface — an opaque surface at the same z-order rendered over it, so the tap opened a panel that was visually absent. One root `Box` now wraps the whole screen body with the episodes drawer as its LAST child — the sheet composes after (over) everything, both orientations, and the portrait bottom-sheet mount is gone.

## 6. Downloads: VALIDATED, the bounded DNS wait, and the preserved partials (D-767)

The offline-resume error needed three more layers on top of round 122's fail-closed check. (a) **`NET_CAPABILITY_VALIDATED`** — INTERNET is the network's DECLARED capability (a dead VPN, cellular with no data, a lingering Wi-Fi all declare it); VALIDATED is the OS having actually reached the network. The check now requires both, is `internal` (shared by the service's evaluateAndNotify), and logs the full decision (`hasInternet validated transports wifiOnly → verdict`). (b) **The bounded DNS wait** — the heal sweep covers false ERRORs from a past outage, but a DNS failure DURING a passing check (the device report) burned straight to ERROR: DNS-class failures (`UnknownHostException` in the cause chain, or the unable-to-resolve message) now WAIT regardless of the capability check, bounded at 2 consecutive online-check failures before honestly ERRORing. (c) **The partials survive** — `HttpDownloader`'s catch branches now classify the failure (`isTransportFailureChain`, depth-capped) and call `cleanupTask(preserveForResume = transport)`: the Range offset, the `.chunks` sidecar, and the HLS state file all survive a transport death, so the healed resume continues instead of "resuming from the very start"; `retry()` is the deliberate opposite (discard the partial, restart clean — a retry after corruption must not trust it), and a server that ignores the Range header (200 instead of 206) logs that it restarted from 0.

## 7. The drag rebuild (D-768)

"Way too glitchy" was the variable-height swap jank: the round-122 rows measured differently per content, so every midpoint swap re-measured half the list. The rows are FIXED 52dp now (single-line compact content: "episode — anime" + one status line), `Modifier.animateItem()` animates the neighbors out of the way, the `pointerInput` keys on the ITEM identity (not the index — a keyed gesture handler can't die mid-drag on a recomposition), and the dragging row highlights `surfaceVariant`. The pinned running rows, the commit-on-drop, and the scheduler contract are unchanged.

## 8. The staleness batch (D-769)

"Refresh doesn't update the DB everywhere" was five persist paths writing raw fetch values (a sparse fetch WIPED stored fields with nulls) or not persisting at all. The AniList twin (D-248) already null-merged; the extension paths now match its discipline: **F1** `resolveContentForExtension` (both the cross-source link branch and the new-row branch) merges every ext field against the existing row before persisting; **F2** the reopen silent refresh merges the sparse fetch into the cached base and persists the merged result; **F3** the reopen enrichment (`loadLinkedSource`'s minimal-base branch) now PERSISTS its fetch (it updated memory only — the DB stayed blank and every reopen re-fetched into nothing); **F4** `refreshExtensionAxis` persists the FULL field set (it wrote only cover+description — a refresh never landed genres/status/author/year/score in the DB, which is exactly "the tags were not being shown, and I had to refresh… and STILL nothing"); **F5** the LIBRARY TITLE sync — `linkExtensionToExisting`'s KDoc claimed "updates the main_entry if different" but the code never touched the title; it now does when the extension axis is the displayed identity, and both axis refreshes sync `main_entry.title` the same way (the user's "library showed the old name until I refreshed" — the refresh updated the screen, never the DB title the library reads).
